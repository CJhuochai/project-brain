## 真实工作区

Windows 上使用发布二进制执行 `scripts/verify-v2.ps1`：发现 30 个仓库（含默认分支未知的工作区根仓库），索引 11,277 个文件。检索 `VisitActivityController`、`ApprovalApplication`、`访校活动`、`groupSubmit` 均有证据，前三组代码词/方法词的首项为对应精确规范化符号；需求分析首选学生仓库。四次检索实测约 4.2–4.7 秒，这是一轮本机样本，不代表整体性能。

符号 ID 上下文、详情展开、类与方法业务流、反向影响、契约列表、MCP initialize/tools/list/analyze_requirement 均成功。该符号摘要 JSON 22,419 字节，详情 52,755 字节；这只比较返回内容大小，没有测量 Agent 总 token 或整体任务成本。

前后保存的业务仓库 Git status 与 refs 完全一致，Git 查询禁用可选锁；没有执行 fetch、checkout、业务构建或业务测试。首轮长时间全量索引期间观察到外部仓库状态变化，因此首轮不计为只读状态验收通过；稳定后使用发布二进制重跑通过。热状态的 status 请求约 8 秒，不是首次全量索引耗时；首次全量重建耗时约十分钟，尚无同环境的前后性能比较。

该工作区存在约 16 万条提取诊断，包括未绑定的普通对象调用；图查询另有源码归属诊断。契约样本达到 100 条预算，方法流有未解析关系，需求报告达到 200 条证据预算；这些结果明确返回 `complete: false`。检查成功说明接口和缺口披露正常，不证明所有关系准确或业务覆盖完整。

已安装的最终 v2.0.0 二进制在生产数据目录重跑同一脚本通过（snapshot-017），Git status/refs 再次完全一致。MCP 配置 TOML 解析成功；插件技能与安装缓存哈希相同。升级前的 4 份报告、1 条反馈、规则及规则快照与备份逐行一致，旧报告 CLI 读取成功。旧二进制、配置、插件源和 v1 索引备份保留用于回滚。
