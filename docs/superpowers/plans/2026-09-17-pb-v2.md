# Project Brain 2.0 Implementation Plan

**Goal:** Implement all six authorized improvements and publish v2.0.0.

**Architecture:** Keep Go, SQLite/FTS5, immutable snapshots and read-only business repositories. Resolve symbols within repository boundaries and cross repositories only through explicit contracts. All limits and static-analysis gaps are observable.

**Spec:** The six points approved in this conversation: ranked retrieval; symbol identities; completeness; business flows; contracts; compact context.

## Global constraints
- No network/upload/build/test/write against business repositories.
- Existing MCP tools retained; search result envelope is documented as a v2 change.
- Reports and feedback in control.sqlite survive upgrades; reindex only in staging.
- No embedding runtime, graph database migration or web UI required.

## Tasks
- [ ] 1. Search: reuse FTS5, normalize identifiers/CJK, exact-match priority, fuse rankings, deduplicate and globally rank requirement evidence; expose truncation. Files: query/search.go, query/search_test.go, requirement/analyze.go.
- [ ] 2. Extract: method signatures/ranges and call arity; conservative receiver binding; static Spring routes, Feign/Dubbo/MQ contracts and configuration service identity. Files: extract/types.go, extract/java_v2.go, extract/contracts.go and tests.
- [ ] 3. Storage/graph: additive schema, staged reindex, stable symbol IDs, repository-scoped resolution, ambiguity/unresolved metadata, reverse impact and bounded traversal. Files: storage/db.go, evidence.go, indexer/index.go, query/graph.go, trace.go and tests.
- [ ] 4. Contract bridge/flows: service-aware HTTP, qualified Dubbo and broker-aware MQ matching; no guessed links; flow summaries with stages, cross-repository hops and evidence. Files: query/contracts.go, context.go, requirement/analyze.go and tests.
- [ ] 5. Public integration: MCP/CLI context, contracts, flows; validated scopes/limits; provenance and persisted report completeness. Files: service/service.go, mcp/server.go, app/app.go, report/report.go and tests.
- [ ] 6. Acceptance/release: regression tests, real read-only samples, Go vet, four-platform artifacts/checksums, bilingual docs, plugin update, PR merge, tag release, installed binary/cache and local main synchronization.

## Verification cases
- Exact symbol beats broad early matches; Chinese and camelCase work; repeated keywords do not inflate candidates; FTS error differs from zero hits.
- Same simple/full name across repositories cannot link implicitly; same-arity overload remains ambiguous; signatures and arity resolve safe cases.
- 21 branches disclose path truncation; depth, cycles, unresolved targets and parsing diagnostics are surfaced.
- End-to-end controller/application/mapper/table flow and explicit cross-service paths retain provenance.
- HTTP same path/wrong service or verb never links; Dubbo requires qualified interface; MQ requires known broker and exact topic. Dynamic/config ambiguity is unresolved.
- Context summary/detail and scope/limit validation are tested through service/MCP/CLI; legacy reports remain readable; failed migration never replaces active snapshot.
